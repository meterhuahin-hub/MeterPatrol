# MeterPatrol บน Google Apps Script + Google Sheets

เวอร์ชันนี้ใช้บัญชี Google ของเจ้าหน้าที่ ไม่ใช้บัญชี/รหัสผ่านของเว็บ Python และไม่ต้องใช้ Render

## สร้างและเผยแพร่ด้วยบัญชี Google ของคุณ
1. สร้าง Google Sheets สำหรับงานสำรวจ แล้วเลือก **ส่วนขยาย → Apps Script**
2. คัดลอก `Code.gs` ลงไฟล์สคริปต์ สร้างไฟล์ HTML ชื่อ `Index`, `Client`, `Styles` แล้วคัดลอกเนื้อหาจากไฟล์ชื่อเดียวกันในโฟลเดอร์นี้
3. ในการตั้งค่าโปรเจกต์ เปิดการแสดงไฟล์ `appsscript.json` แล้วแทนเนื้อหาด้วยไฟล์ที่เตรียมไว้
4. ใน **Project Settings → Script properties** เพิ่ม:
   - `SPREADSHEET_ID`: ID จาก URL ของ Google Sheets ระหว่าง `/d/` กับ `/edit`
   - `ALLOWED_EMAILS`: อีเมล Google ของเจ้าหน้าที่รวมถึงผู้ดูแล คั่นด้วย comma ไม่มีรหัสผ่าน
5. แชร์ Google Sheets ให้เจ้าหน้าที่เหล่านี้เป็น **Editor** เพราะเว็บทำงานด้วยสิทธิ์ของผู้เข้าใช้ ไม่เปิดแชร์แบบ Anyone with link
6. เลือก **Deploy → New deployment → Web app** ตั้ง **Execute as: User accessing the web app** และ **Who has access: Anyone with Google account** (หรือตัวเลือกภายในองค์กรที่ครอบคลุมเจ้าหน้าที่) ห้ามเลือก Anonymous หรือ Execute as me
7. อนุญาตสิทธิ์ Google แล้วคัดลอก URL `/exec` ให้เจ้าหน้าที่ เจ้าหน้าที่แต่ละคนต้องเข้าสู่ระบบ Google และอนุญาตสิทธิ์ของแอปเอง
8. ทดสอบด้วยบัญชีที่อยู่ใน allowlist และบัญชีที่ไม่อยู่ใน allowlist ก่อนใช้งานจริง นโยบาย Workspace/OAuth ขององค์กรอาจจำกัดการเผยแพร่หรือผู้ใช้ภายนอก ผู้ดูแล Google ต้องอนุญาตตามนโยบายองค์กร

เมื่อแก้โค้ด ให้ Deploy → Manage deployments → Edit → New version เพื่ออัปเดต URL เดิม

## การใช้งานและข้อจำกัด
- อ่าน/บันทึกต้องตรวจสอบ Google email ฝั่งเซิร์ฟเวอร์ทุกครั้ง ถ้า Google ไม่ส่ง email ให้จะปฏิเสธการเข้าถึง
- ใช้ชีตชื่อ `MeterPatrol` ระบบสร้างหัวตารางเมื่อบันทึกหรือโหลดครั้งแรก ห้ามแก้หัวตารางหรือคอลัมน์ข้อมูล JSON
- บันทึกวันที่ ผู้สำรวจ มิเตอร์ จำนวนอุปกรณ์ชำรุด/ใหม่ และอีเมลผู้บันทึก ค้นหาและพิมพ์รายงาน/PDF จากเว็บ
- ชื่อผู้สำรวจเป็นข้อความที่กรอก ส่วนบัญชีผู้บันทึกมาจาก Google และผู้ใช้ปลอมผ่านฟอร์มไม่ได้
- การส่งซ้ำด้วยรหัสคำขอเดิมไม่สร้างรายการซ้ำ มี Script Lock ป้องกันการเขียนพร้อมกัน
- ข้อมูลเต็มอยู่ในคอลัมน์ JSON รายงานอ่านจากข้อมูลนี้ การแก้คอลัมน์อื่นใน Sheets ไม่ปรับรายงาน
- เจ้าหน้าที่ที่เป็น Editor แก้ข้อมูลใน Sheets โดยตรงได้ และสำหรับโปรเจกต์ bound อาจเข้าถึง/แก้ Apps Script ได้ด้วย จึงเหมาะกับทีมที่เชื่อถือได้ allowlist ไม่ใช่ขอบเขตป้องกันผู้ที่มีสิทธิ์แก้โปรเจกต์
- หากต้องแยกเจ้าหน้าที่ออกจากการแก้ Sheets/สคริปต์ ต้องเปลี่ยนสถาปัตยกรรมการยืนยันตัวตนและสิทธิ์ก่อนใช้งาน
- หนึ่งเซลล์จำกัดขนาดข้อมูล และ Apps Script มี quota/เวลารัน ระบบอ่านประวัติทั้งหมด เหมาะกับทีมขนาดเล็ก ก่อนข้อมูลจำนวนมากควรเพิ่ม pagination/ฐานข้อมูล
- ระบบไม่ส่งอีเมล ไม่ออกจาก Google account แทนผู้ใช้ และไม่ย้ายข้อมูล SQLite เดิมอัตโนมัติ

## การตรวจสอบ
```sh
node apps-script/test.cjs
```
ชุดทดสอบนี้จำลอง Google APIs เพื่อตรวจ logic ไม่ใช่การ deploy หรือ OAuth จริง การทดสอบ Google จริงยังต้องทำผ่านบัญชีและ deployment ของคุณ

## ตรวจรับหลังเผยแพร่
- บัญชีใน allowlist เปิดเว็บได้ บัญชีนอก allowlist และผู้ไม่เข้าสู่ระบบเข้าไม่ได้
- บันทึกเลขมิเตอร์ `00001` และอุปกรณ์ชำรุด 2 ใหม่ 3 แล้วตรวจข้อมูลใน Sheets
- โหลดเว็บใหม่ ตรวจประวัติ ค้นหา เปิดรายงาน ตรวจยอดรวม และพิมพ์ PDF
- เปิดสองหน้าต่างแล้วบันทึกต่างรายการ ตรวจว่ามีทั้งสองแถวและไม่มีข้อมูลทับกัน
- สำรอง Sheets เป็นระยะ และจำกัดผู้มีสิทธิ์แก้โปรเจกต์
