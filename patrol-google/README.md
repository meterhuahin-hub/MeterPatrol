# เชื่อมฟอร์ม Patrol ที่ส่งมากับ Google Sheets

ชุดไฟล์นี้รักษาช่องสำรวจ WBS/TR/PEA พัสดุเก่า-ใหม่ GPS และรูปก่อน-หลังของฟอร์มที่ผู้ใช้ส่งมา ใช้แทน HTML แบบ standalone เดิม ห้ามเปิดไฟล์ Index.html แล้วคาดว่าจะบันทึกได้ ต้องเปิดผ่าน Apps Script deployment เท่านั้น

ชีตเป้าหมาย: https://docs.google.com/spreadsheets/d/1DydK1q8PZELyk2gTFmtxxiUtgSz6EYxRncw1Ep7JDSg/edit
ระบบบันทึกในแท็บ `DATA` ตามหัวตาราง 44 คอลัมน์ที่ผู้ใช้ระบุ แยก Latitude/Longitude และอ่านประวัติจาก DATA โดยตรง ไม่ลบหรือย้ายข้อมูลใน PatrolSurvey เดิม และไม่เพิ่มคอลัมน์ JSON

บัญชีผู้บันทึกและ fingerprint สำหรับป้องกันส่งซ้ำเก็บในหมายเหตุเซลล์ Record ID ไม่ใช่คอลัมน์เพิ่ม ห้ามลบหมายเหตุนี้หากยังต้องส่งคำขอซ้ำ หากหัวตารางไม่ตรง ระบบปฏิเสธการเขียนโดยไม่แก้ตารางเดิม

## อัปเดตลิงก์เว็บเดิม
1. เปิดโปรเจกต์ Apps Script ที่เป็นเจ้าของ URL `/exec` เดิม (หากเปิดจาก Sheets แล้วเป็นคนละโปรเจกต์ ต้องเข้าโปรเจกต์ที่ deploy URL นั้น)
2. สำรองโค้ดเดิมก่อน จากนั้นแทน `Code.gs` และสร้าง/แทน HTML ชื่อ `Index` ด้วยไฟล์ในโฟลเดอร์นี้ หากมีไฟล์ .gs อื่นประกาศ doGet/listPatrol/savePatrol ซ้ำ ให้สำรองแล้วเอาฟังก์ชันซ้ำออก
3. เปิดการแสดง manifest ใน Project Settings แล้วแทน `appsscript.json` ด้วยไฟล์นี้
4. เพิ่ม Script property `ALLOWED_EMAILS` เป็นอีเมล Google ของเจ้าหน้าที่รวมผู้ดูแล คั่นด้วย comma
5. แชร์ Google Sheets เป้าหมายให้บัญชีเจ้าหน้าที่เป็น Editor ไม่มีรหัสผ่านที่ต้องกรอกหรือส่งในแชต
6. ถ้าใช้รูป: สร้างโฟลเดอร์ Google Drive แชร์ให้เจ้าหน้าที่เป็น Editor แล้วเพิ่ม `PHOTO_FOLDER_ID` ใน Script properties เป็น ID จาก URL โฟลเดอร์ รูปเก็บเป็นไฟล์ส่วนตัวในโฟลเดอร์นี้ ไม่แชร์สาธารณะ รูป JPEG ไม่เกินประมาณ 2 MB ต่อรูป ถ้าไม่ตั้งโฟลเดอร์ยังบันทึกงานที่ไม่แนบรูปได้
7. Deploy → Manage deployments → Edit → New version ตั้ง Execute as **User accessing the web app** และ Who has access **Anyone with Google account** (หรือเฉพาะองค์กร) แล้ว Deploy เพื่อรักษา URL เดิม Google อาจให้อนุญาตสิทธิ์ใหม่เพราะเพิ่ม Drive scope
8. เปิด URL `/exec` ไม่ใช่ HTML ที่ดาวน์โหลดไว้ เมื่ออ่านชีตสำเร็จ หน้าเว็บจะแสดง “โหลดข้อมูลจาก Google Sheets แล้ว” จึงเปิดให้บันทึก

ข้อสำคัญ: เจ้าหน้าที่ที่เป็น Editor อาจแก้ข้อมูล Sheets และ Apps Script ที่ผูกกับชีตได้ เหมาะกับทีมที่เชื่อถือกัน Google Workspace อาจจำกัด OAuth/การเผยแพร่ ผู้ดูแล Google ต้องแก้สิทธิ์ที่จำเป็น

## ทดสอบจริงหลัง deploy
กรอกวันที่, WBS หรือ TR, PEA `00001`, จำนวนพัสดุ แล้วบันทึก ตรวจข้อความ “Google Sheets ยืนยันการบันทึกแล้ว” และแถวใหม่ในแท็บ DATA โหลดเว็บใหม่เพื่อยืนยันข้อมูลจากเซิร์ฟเวอร์ ทดสอบรูปและเปิดลิงก์ Drive ด้วยบัญชีเจ้าหน้าที่ ทดสอบบัญชีนอก allowlist ว่าเข้าไม่ได้

หน้าเว็บไม่ใช้ no-cors หรือ localStorage เพื่ออ้างว่าส่งสำเร็จอีกต่อไป การลบข้อมูลในชีตไม่ได้เปิดให้ทำจากฟอร์ม ภาพที่ส่งออกสำรองเป็นลิงก์ ไม่รวมไฟล์ภาพ GPS/กล้องใน iframe ของ Apps Script อาจถูกเบราว์เซอร์จำกัด โปรดทดสอบบนอุปกรณ์จริง ระบบยังอ่านประวัติทั้งหมดจึงเหมาะกับทีมขนาดเล็ก สำรอง Sheets/Drive เป็นระยะ

ไม่มีการย้ายข้อมูล localStorage เดิมอัตโนมัติ หากกรอกในฟอร์มเดิมให้ส่งออก JSON สำรองก่อน

## อัปเดตจากเวอร์ชัน PatrolSurvey
แทนเฉพาะ `Code.gs` ด้วยเวอร์ชันล่าสุด แล้ว Deploy → Manage deployments → Edit → New version → Deploy ลิงก์เดิมยังใช้ได้ ไฟล์ Index และ Script properties เดิมใช้ต่อได้ สำรองชีตก่อนอัปเดต ข้อมูลเก่าใน PatrolSurvey ไม่ย้ายอัตโนมัติ เพื่อป้องกันการเพิ่มซ้ำ

## ทดสอบ logic ในเครื่อง
`node patrol-google/test.cjs` จำลอง Google APIs ไม่ใช่การทดสอบ deployment จริง

รูปใหม่ตั้งชื่อ `<PEA>_ก่อน_<รหัสบันทึก>.jpg` และ `<PEA>_หลัง_<รหัสบันทึก>.jpg` รักษาศูนย์นำหน้า แทนอักขระที่ไม่เหมาะกับชื่อไฟล์ด้วย `_` ถ้าไม่กรอก PEA ใช้ `ไม่ระบุ-PEA` ไม่เปลี่ยนชื่อรูปเดิมอัตโนมัติ

## หน้าเว็บ 5 หน้า
Index.html มีเมนูหน้าหลัก (สถิติและงานล่าสุด), บันทึกงาน, ประวัติ (ค้นหา PEA/TR/WBS และช่วงวันที่), รายงาน (งานทั้งหมด/ตามตัวกรอง/เฉพาะงาน), จัดการข้อมูล (โหลดใหม่และลิงก์ Sheets) หน้าเว็บยังไม่มีการแก้ไข/ลบรายการโดยตรง การตั้งค่าสิทธิ์ทำใน Apps Script ตามเดิม
อัปเดตไฟล์ Index.html ด้วยเวอร์ชันล่าสุด และ Deploy เวอร์ชันใหม่เพื่อใช้เมนู ไม่จำเป็นต้องเปลี่ยน Code.gs หากใช้รุ่น DATA/ชื่อรูป PEA ล่าสุดแล้ว

## หน้าผู้รับจ้าง: WBS → แผนที่ → PEA → ส่งมอบ
- เพิ่มเมนูผู้รับจ้าง รวมงานตาม WBS ที่ตรงกัน (ตัดช่องว่างหัวท้าย) งานไม่มี WBS จะแสดงจำนวนแจ้งเตือนและต้องเติม WBS ก่อน
- แสดงหมุดจาก Latitude/Longitude ที่ถูกต้อง กดหมุดหรือเปิดงานในรายการเพื่อดู PEA และลิงก์นำทาง Google Maps งานไม่มีพิกัดยังอยู่ในรายการ แต่ไม่มีหมุด/ปุ่มนำทาง
- พื้นแผนที่ OpenStreetMap ผ่าน Leaflet 1.9.4 ไม่ต้องใช้ API key โหลดรูปแผนที่จาก tile.openstreetmap.org; ต้องมีอินเทอร์เน็ต การใช้งานจำนวนมากควรเลือกผู้ให้บริการ tile ที่รองรับปริมาณงาน
- แนบรูปปฏิบัติ 1 และ 2 (ถ่ายจากมือถือหรือเลือกรูป) ย่อเป็น JPEG แล้วกดส่งมอบ เซิร์ฟเวอร์ตรวจรูปครบ ตรวจงานจริงและสิทธิ์ก่อนบันทึก ไม่รับ PEA/WBS จาก client แทนข้อมูลจริง
- รูปชื่อ `<PEA>_ปฏิบัติ1_<รหัสคำขอ>.jpg` และรูปที่ 2 ตามรูปแบบเดียวกัน เก็บใน PHOTO_FOLDER_ID เดิม รูปสำรวจเดิมใน DATA ไม่ถูกแทนที่
- บันทึกส่งมอบแยกในแท็บ `ContractorWork` พร้อมบัญชีผู้ส่งมอบ เวลา และลิงก์รูปทั้งสอง แล้วปรับคอลัมน์ผลสำรวจใน DATA เป็น `ส่งมอบงาน` หมุดสีฟ้าอิงรายการส่งมอบที่มีรูปครบ ไม่อิงเพียงข้อความสถานะสำรวจ
- ส่งซ้ำจากหน้าฟอร์มเดิมไม่สร้างรายการซ้ำ งานที่ส่งมอบแล้วดูรูปได้และไม่เปิดให้ส่งมอบทับ รายการอัปเดตหลังบันทึกหรือกดโหลดข้อมูลล่าสุด

### อัปเดต Apps Script สำหรับหน้าผู้รับจ้าง
1. แทน `Code.gs` และ HTML `Index` ด้วยเวอร์ชันใหม่ในโฟลเดอร์นี้
2. สร้างไฟล์ HTML เพิ่มชื่อ **Leaflet** แล้วคัดลอกเนื้อหา `Leaflet.html` ทั้งหมด (มี CSS/JavaScript ที่รวมไว้แล้ว ไม่ต้องแก้)
3. คง `ALLOWED_EMAILS` และ `PHOTO_FOLDER_ID` เดิม เพิ่มอีเมลผู้รับจ้างใน ALLOWED_EMAILS และแชร์ Sheets/โฟลเดอร์รูปเป็น Editor ให้บัญชีดังกล่าว
4. Deploy → Manage deployments → Edit → New version → Deploy แล้วเปิด /exec เดิม

เมนูผู้รับจ้างเป็นหน้าการทำงาน ไม่ใช่การแยกสิทธิ์เป็น role ผู้ที่อยู่ใน ALLOWED_EMAILS ทุกคนยังเข้าถึงงานทุก WBS ได้ และ Editor แก้ Sheets/โปรเจกต์ที่ bound ได้ ถ้าต้องจำกัดผู้รับจ้างเฉพาะ WBS ต้องเพิ่มการกำหนดสิทธิ์แยกอีกขั้น

### ตรวจรับ
เลือก WBS ที่มีอย่างน้อย 2 งาน ตรวจว่าหมุดไม่ปน WBS อื่น กดหมุดแล้วตรวจ PEA/พิกัดและนำทาง ทดสอบส่งมอบด้วยรูปครบ 2 รูป ตรวจแถว ContractorWork และผลสำรวจใน DATA หมุดต้องเป็นสีฟ้าหลังบันทึกสำเร็จและยังเป็นสีฟ้าหลังโหลดใหม่ งานพิกัดว่างต้องไม่มีหมุด และงานส่งมอบแล้วต้องดูรูปได้แต่ส่งทับไม่ได้ ทดสอบบนอุปกรณ์จริงด้วยบัญชีผู้รับจ้าง; Apps Script iframe/เบราว์เซอร์อาจจำกัดกล้องหรือ GPS จึงมีตัวเลือกเลือกรูปจากเครื่อง

`node patrol-google/test-contractor.cjs` ตรวจ logic ส่งมอบด้วย Google APIs จำลอง รวมกรณีส่งซ้ำและกู้คืนหลังการอัปเดตสถานะล้มเหลว การทดสอบจำลองไม่ยืนยัน Google OAuth/Drive/tiles ของ deployment จริง
Leaflet vendored จาก npm package 1.9.4 โดยตรวจ SHA512 integrity ของ archive แล้ว มี license ใน LEAFLET-LICENSE.txt

## ลิงก์รูปปฏิบัติงานใน DATA
หลังอัปเดต Code.gs ระบบเติมหัวตาราง AS `รูปปฏิบัติงาน 1` และ AT `รูปปฏิบัติงาน 2` โดยไม่เพิ่มแทรกระหว่างคอลัมน์เดิม งานส่งมอบใหม่และการส่งซ้ำที่ยืนยันแล้วเติม URL ของรูปทั้งสองลง DATA เช่นเดียวกับลิงก์รูปสำรวจ AQ/AR หาก AS/AT มีหัวตารางอื่นหรือข้อมูลที่ไม่มีหัวตาราง ระบบจะหยุดแทนการเขียนทับ

สำหรับรูปที่ส่งมอบไปแล้ว: ใน Apps Script เลือกฟังก์ชัน `syncContractorPhotos` แล้วกด Run (บัญชีต้องอยู่ใน ALLOWED_EMAILS) ฟังก์ชันสร้างหัวตารางและคัดลอกลิงก์จาก ContractorWork ตาม Record ID เฉพาะช่องที่ว่างหรือมีลิงก์ตรงกัน รันซ้ำได้ ถ้าพบลิงก์อื่นหรือ Record ID ซ้ำจะข้ามแถวนั้นและรายงาน conflicts ใน Execution log ไม่แก้รูปสำรวจเดิมหรือไฟล์รูปใน Drive

บันทึก Code.gs และ Deploy เวอร์ชันใหม่เพื่อให้การส่งมอบครั้งต่อไปใช้โค้ดใหม่ Index.html ไม่ต้องเปลี่ยนสำหรับคอลัมน์รูปนี้
