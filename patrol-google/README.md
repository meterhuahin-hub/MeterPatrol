# เชื่อมฟอร์ม Patrol ที่ส่งมากับ Google Sheets

ชุดไฟล์นี้รักษาช่องสำรวจ WBS/TR/PEA พัสดุเก่า-ใหม่ GPS และรูปก่อน-หลังของฟอร์มที่ผู้ใช้ส่งมา ใช้แทน HTML แบบ standalone เดิม ห้ามเปิดไฟล์ Index.html แล้วคาดว่าจะบันทึกได้ ต้องเปิดผ่าน Apps Script deployment เท่านั้น

ชีตเป้าหมาย: https://docs.google.com/spreadsheets/d/1DydK1q8PZELyk2gTFmtxxiUtgSz6EYxRncw1Ep7JDSg/edit
ระบบบันทึกในแท็บ `DATA` ตามหัวตาราง 44 คอลัมน์ที่ผู้ใช้ระบุ แยก Latitude/Longitude และอ่านประวัติจาก DATA โดยตรง ไม่ลบหรือย้ายข้อมูลใน PatrolSurvey เดิม และไม่เพิ่มคอลัมน์ JSON

บัญชีผู้บันทึกและ fingerprint สำหรับป้องกันส่งซ้ำเก็บในหมายเหตุเซลล์ Record ID ไม่ใช่คอลัมน์เพิ่ม ห้ามลบหมายเหตุนี้หากยังต้องส่งคำขอซ้ำ หากหัวตารางไม่ตรง ระบบปฏิเสธการเขียนโดยไม่แก้ตารางเดิม

## อัปเดตลิงก์เว็บเดิม
1. เปิดโปรเจกต์ Apps Script ที่เป็นเจ้าของ URL `/exec` เดิม (หากเปิดจาก Sheets แล้วเป็นคนละโปรเจกต์ ต้องเข้าโปรเจกต์ที่ deploy URL นั้น)
2. สำรองโค้ดเดิมก่อน จากนั้นแทน `Code.gs` และสร้าง/แทน HTML ชื่อ `Index` ด้วยไฟล์ในโฟลเดอร์นี้ หากมีไฟล์ .gs อื่นประกาศ doGet/listPatrol/savePatrol ซ้ำ ให้สำรองแล้วเอาฟังก์ชันซ้ำออก
3. เปิดการแสดง manifest ใน Project Settings แล้วแทน `appsscript.json` ด้วยไฟล์นี้
4. เพิ่ม Script property `ALLOWED_EMAILS` เป็นอีเมล Google ของเจ้าหน้าที่รวมผู้ดูแล คั่นด้วย comma
5. แชร์ Google Sheets เป้าหมายให้บัญชีเจ้าหน้าที่เป็น Editor ไม่มีรหัสผ่านที่ต้องกรอกหรือส่งในแชต
6. ถ้าใช้รูป: สร้างโฟลเดอร์ Google Drive แชร์ให้เจ้าหน้าที่เป็น Editor แล้วเพิ่ม `PHOTO_FOLDER_ID` ใน Script properties เป็น ID จาก URL โฟลเดอร์ รูปเก็บเป็นไฟล์ส่วนตัวในโฟลเดอร์นี้ ไม่แชร์สาธารณะ รูป JPEG ไม่เกินประมาณ 2 MB ต่อรูป ถ้าไม่ตั้งโฟลเดอร์ยังบันทึกงานที่ไม่แนบรูปได้
7. Deploy → Manage deployments → Edit → New version ตั้ง Execute as **User accessing the web app** และ Who has access **Anyone with Google account** (หรือเฉพาะองค์กร) แล้ว Deploy เพื่อรักษา URL เดิม Google อาจให้อนุญาตสิทธิ์ใหม่เพราะเพิ่ม Drive scope
8. เปิด URL `/exec` ไม่ใช่ HTML ที่ดาวน์โหลดไว้ เมื่ออ่านชีตสำเร็จ หน้าเว็บจะแสดง “โหลดข้อมูลจาก Google Sheets แล้ว” จึงเปิดให้บันทึก

ข้อสำคัญ: เจ้าหน้าที่ที่เป็น Editor อาจแก้ข้อมูล Sheets และ Apps Script ที่ผูกกับชีตได้ เหมาะกับทีมที่เชื่อถือกัน Google Workspace อาจจำกัด OAuth/การเผยแพร่ ผู้ดูแล Google ต้องแก้สิทธิ์ที่จำเป็น

## ทดสอบจริงหลัง deploy
กรอกวันที่, WBS หรือ TR, PEA `00001`, จำนวนพัสดุ แล้วบันทึก ตรวจข้อความ “Google Sheets ยืนยันการบันทึกแล้ว” และแถวใหม่ในแท็บ DATA โหลดเว็บใหม่เพื่อยืนยันข้อมูลจากเซิร์ฟเวอร์ ทดสอบรูปและเปิดลิงก์ Drive ด้วยบัญชีเจ้าหน้าที่ ทดสอบบัญชีนอก allowlist ว่าเข้าไม่ได้

หน้าเว็บไม่ใช้ no-cors หรือ localStorage เพื่ออ้างว่าส่งสำเร็จอีกต่อไป การลบข้อมูลในชีตไม่ได้เปิดให้ทำจากฟอร์ม ภาพที่ส่งออกสำรองเป็นลิงก์ ไม่รวมไฟล์ภาพ GPS/กล้องใน iframe ของ Apps Script อาจถูกเบราว์เซอร์จำกัด โปรดทดสอบบนอุปกรณ์จริง ระบบยังอ่านประวัติทั้งหมดจึงเหมาะกับทีมขนาดเล็ก สำรอง Sheets/Drive เป็นระยะ

ไม่มีการย้ายข้อมูล localStorage เดิมอัตโนมัติ หากกรอกในฟอร์มเดิมให้ส่งออก JSON สำรองก่อน

## อัปเดตจากเวอร์ชัน PatrolSurvey
แทนเฉพาะ `Code.gs` ด้วยเวอร์ชันล่าสุด แล้ว Deploy → Manage deployments → Edit → New version → Deploy ลิงก์เดิมยังใช้ได้ ไฟล์ Index และ Script properties เดิมใช้ต่อได้ สำรองชีตก่อนอัปเดต ข้อมูลเก่าใน PatrolSurvey ไม่ย้ายอัตโนมัติ เพื่อป้องกันการเพิ่มซ้ำ

## ทดสอบ logic ในเครื่อง
`node patrol-google/test.cjs` จำลอง Google APIs ไม่ใช่การทดสอบ deployment จริง

รูปใหม่ตั้งชื่อ `<PEA>_ก่อน_<รหัสบันทึก>.jpg` และ `<PEA>_หลัง_<รหัสบันทึก>.jpg` รักษาศูนย์นำหน้า แทนอักขระที่ไม่เหมาะกับชื่อไฟล์ด้วย `_` ถ้าไม่กรอก PEA ใช้ `ไม่ระบุ-PEA` ไม่เปลี่ยนชื่อรูปเดิมอัตโนมัติ

## หน้าเว็บ 5 หน้า
Index.html มีเมนูหน้าหลัก (สถิติและงานล่าสุด), บันทึกงาน, ประวัติ (ค้นหา PEA/TR/WBS และช่วงวันที่), รายงาน (งานทั้งหมด/ตามตัวกรอง/เฉพาะงาน), จัดการข้อมูล (โหลดใหม่และลิงก์ Sheets) หน้าเว็บยังไม่มีการแก้ไข/ลบรายการโดยตรง การตั้งค่าสิทธิ์ทำใน Apps Script ตามเดิม
อัปเดตไฟล์ Index.html ด้วยเวอร์ชันล่าสุด และ Deploy เวอร์ชันใหม่เพื่อใช้เมนู ไม่จำเป็นต้องเปลี่ยน Code.gs หากใช้รุ่น DATA/ชื่อรูป PEA ล่าสุดแล้ว

## หน้าผู้รับจ้าง: WBS → แผนที่ → PEA → ส่งมอบ
- เพิ่มเมนูผู้รับจ้าง รวมงานตาม WBS ที่ตรงกัน (ตัดช่องว่างหัวท้าย) งานไม่มี WBS จะแสดงจำนวนแจ้งเตือนและต้องเติม WBS ก่อน
- แสดงหมุดจาก Latitude/Longitude ที่ถูกต้อง กดหมุดหรือเปิดงานในรายการเพื่อดู PEA และลิงก์นำทาง Google Maps งานไม่มีพิกัดยังอยู่ในรายการ แต่ไม่มีหมุด/ปุ่มนำทาง
- พื้นแผนที่ OpenStreetMap ผ่าน Leaflet 1.9.4 ไม่ต้องใช้ API key โหลดรูปแผนที่จาก tile.openstreetmap.org; ต้องมีอินเทอร์เน็ต การใช้งานจำนวนมากควรเลือกผู้ให้บริการ tile ที่รองรับปริมาณงาน
- แนบรูปปฏิบัติ 1 และ 2 (ถ่ายจากมือถือหรือเลือกรูป) ย่อเป็น JPEG แล้วกดส่งมอบ เซิร์ฟเวอร์ตรวจรูปครบ ตรวจงานจริงและสิทธิ์ก่อนบันทึก ไม่รับ PEA/WBS จาก client แทนข้อมูลจริง
- รูปชื่อ `<PEA>_ปฏิบัติ1_<รหัสคำขอ>.jpg` และรูปที่ 2 ตามรูปแบบเดียวกัน เก็บใน PHOTO_FOLDER_ID เดิม รูปสำรวจเดิมใน DATA ไม่ถูกแทนที่
- บันทึกส่งมอบแยกในแท็บ `ContractorWork` พร้อมบัญชีผู้ส่งมอบ เวลา และลิงก์รูปทั้งสอง แล้วปรับคอลัมน์ผลสำรวจใน DATA เป็น `ส่งมอบงาน` หมุดสีฟ้าอิงรายการส่งมอบที่มีรูปครบ ไม่อิงเพียงข้อความสถานะสำรวจ
- ส่งซ้ำจากหน้าฟอร์มเดิมไม่สร้างรายการซ้ำ งานที่ส่งมอบแล้วดูรูปได้และไม่เปิดให้ส่งมอบทับ รายการอัปเดตหลังบันทึกหรือกดโหลดข้อมูลล่าสุด

### อัปเดต Apps Script สำหรับหน้าผู้รับจ้าง
1. แทน `Code.gs` และ HTML `Index` ด้วยเวอร์ชันใหม่ในโฟลเดอร์นี้
2. สร้างไฟล์ HTML เพิ่มชื่อ **Leaflet** แล้วคัดลอกเนื้อหา `Leaflet.html` ทั้งหมด (มี CSS/JavaScript ที่รวมไว้แล้ว ไม่ต้องแก้)
3. คง `ALLOWED_EMAILS` และ `PHOTO_FOLDER_ID` เดิม เพิ่มอีเมลผู้รับจ้างใน ALLOWED_EMAILS และแชร์ Sheets/โฟลเดอร์รูปเป็น Editor ให้บัญชีดังกล่าว
4. Deploy → Manage deployments → Edit → New version → Deploy แล้วเปิด /exec เดิม

เมนูผู้รับจ้างเป็นหน้าการทำงาน ไม่ใช่การแยกสิทธิ์เป็น role ผู้ที่อยู่ใน ALLOWED_EMAILS ทุกคนยังเข้าถึงงานทุก WBS ได้ และ Editor แก้ Sheets/โปรเจกต์ที่ bound ได้ ถ้าต้องจำกัดผู้รับจ้างเฉพาะ WBS ต้องเพิ่มการกำหนดสิทธิ์แยกอีกขั้น

### ตรวจรับ
เลือก WBS ที่มีอย่างน้อย 2 งาน ตรวจว่าหมุดไม่ปน WBS อื่น กดหมุดแล้วตรวจ PEA/พิกัดและนำทาง ทดสอบส่งมอบด้วยรูปครบ 2 รูป ตรวจแถว ContractorWork และผลสำรวจใน DATA หมุดต้องเป็นสีฟ้าหลังบันทึกสำเร็จและยังเป็นสีฟ้าหลังโหลดใหม่ งานพิกัดว่างต้องไม่มีหมุด และงานส่งมอบแล้วต้องดูรูปได้แต่ส่งทับไม่ได้ ทดสอบบนอุปกรณ์จริงด้วยบัญชีผู้รับจ้าง; Apps Script iframe/เบราว์เซอร์อาจจำกัดกล้องหรือ GPS จึงมีตัวเลือกเลือกรูปจากเครื่อง

`node patrol-google/test-contractor.cjs` ตรวจ logic ส่งมอบด้วย Google APIs จำลอง รวมกรณีส่งซ้ำและกู้คืนหลังการอัปเดตสถานะล้มเหลว การทดสอบจำลองไม่ยืนยัน Google OAuth/Drive/tiles ของ deployment จริง
Leaflet vendored จาก npm package 1.9.4 โดยตรวจ SHA512 integrity ของ archive แล้ว มี license ใน LEAFLET-LICENSE.txt

## ลิงก์รูปปฏิบัติงานใน DATA
หลังอัปเดต Code.gs ระบบเติมหัวตาราง AS `รูปปฏิบัติงาน 1` และ AT `รูปปฏิบัติงาน 2` โดยไม่เพิ่มแทรกระหว่างคอลัมน์เดิม งานส่งมอบใหม่และการส่งซ้ำที่ยืนยันแล้วเติม URL ของรูปทั้งสองลง DATA เช่นเดียวกับลิงก์รูปสำรวจ AQ/AR หาก AS/AT มีหัวตารางอื่นหรือข้อมูลที่ไม่มีหัวตาราง ระบบจะหยุดแทนการเขียนทับ

สำหรับรูปที่ส่งมอบไปแล้ว: ใน Apps Script เลือกฟังก์ชัน `syncContractorPhotos` แล้วกด Run (บัญชีต้องอยู่ใน ALLOWED_EMAILS) ฟังก์ชันสร้างหัวตารางและคัดลอกลิงก์จาก ContractorWork ตาม Record ID เฉพาะช่องที่ว่างหรือมีลิงก์ตรงกัน รันซ้ำได้ ถ้าพบลิงก์อื่นหรือ Record ID ซ้ำจะข้ามแถวนั้นและรายงาน conflicts ใน Execution log ไม่แก้รูปสำรวจเดิมหรือไฟล์รูปใน Drive

บันทึก Code.gs และ Deploy เวอร์ชันใหม่เพื่อให้การส่งมอบครั้งต่อไปใช้โค้ดใหม่ Index.html ไม่ต้องเปลี่ยนสำหรับคอลัมน์รูปนี้

## หน้าช่างผู้ควบคุมงาน
เพิ่มเมนูช่างผู้ควบคุมงาน รวมงานตาม WBS กดหมุดหรือรายการเพื่อดู PEA และนำทาง Google Maps แนบรูปตรวจรับ 2 รูป แล้วเลือก **ผ่าน** (หมุดสีเขียว) หรือ **ไม่ผ่าน** (หมุดสีแดง) เปลี่ยนสีเฉพาะหลังเซิร์ฟเวอร์ยืนยัน ก่อนตรวจใช้สีฟ้าถ้าส่งมอบแล้ว หรือสีส้มถ้ายังไม่ส่งมอบ งานไม่มีพิกัดแสดงเฉพาะรายการ

ผลตรวจและลิงก์รูปตรวจรับเก็บแยกใน `InspectorReviews` พร้อมผู้ตรวจ เวลา และประวัติการตรวจทุกครั้ง ผลล่าสุดใช้บนแผนที่และเขียนลงคอลัมน์ผลสำรวจใน DATA รูปสำรวจ AQ/AR และรูปปฏิบัติ AS/AT ไม่ถูกเปลี่ยน รูปตรวจรับเก็บใน PHOTO_FOLDER_ID เดิม ชื่อ `<PEA>_ตรวจรับ1_<รหัสคำขอ>.jpg` และตรวจรับ2 การตรวจซ้ำต้องเลือกภาพใหม่ครบสองรูปและเก็บประวัติเดิมไว้ การส่งคำขอเดิมซ้ำไม่สร้างซ้ำหรือย้อนผลล่าสุด

อัปเดตเฉพาะ Code.gs และ Index.html แล้ว Deploy เวอร์ชันใหม่ ไฟล์ Leaflet และ manifest เดิมใช้ต่อได้ เพิ่มอีเมลช่างใน ALLOWED_EMAILS และแชร์ Sheets/โฟลเดอร์รูปเป็น Editor การเพิ่มหน้าไม่ใช่การแยก role: บัญชีที่อนุญาตทุกคนยังใช้หน้าตรวจรับได้ หากต้องจำกัดเฉพาะช่างควรเพิ่มสิทธิ์แยกต่างหาก

ทดสอบ logic: `node patrol-google/test-inspector.cjs` (Google APIs จำลอง) ตรวจรับจริงหลัง Deploy: เลือก WBS ตรวจหมุดตรงพิกัด/PEA ถ่ายหรือเลือกรูปสองรูป กดไม่ผ่านตรวจสีแดง จากนั้นตรวจใหม่กดผ่านตรวจสีเขียว โหลดใหม่ตรวจผลล่าสุดและลิงก์รูปใน InspectorReviews การทดสอบเบราว์เซอร์ใน workspace ใช้ Google bridge และพื้นแผนที่จำลอง ไม่ยืนยัน OAuth/Sheets/Drive ของ deployment จริง

## คอลัมน์รูปตรวจรับและภาพที่แสดงในเว็บ
เพิ่ม DATA คอลัมน์ AU `ดูรูปตรวจรับ 1` และ AV `ดูรูปตรวจรับ 2` เป็นลิงก์ Drive เช่น AQ/AR เดิม การบันทึกผลตรวจใหม่หรือส่งซ้ำเติมลิงก์รูปตรวจล่าสุดใน AU/AV เก็บ AS/AT รูปปฏิบัติเดิมไว้

หลังแทน Code.gs ให้เลือกฟังก์ชัน `syncInspectionPhotos` → Run เพื่อสร้างหัวคอลัมน์และเติมลิงก์รูปตรวจที่มีอยู่แล้วจาก InspectorReviews รันซ้ำได้ ช่องที่มีลิงก์ต่างจากประวัติล่าสุดจะถูกข้ามและรายงาน conflicts เพื่อรักษาการแก้ข้อมูลของผู้ใช้ งานตรวจใหม่จะเขียนลิงก์ล่าสุดตามคำสั่งบันทึกผลตรวจ

แทน Index.html และ Deploy เวอร์ชันใหม่เพื่อแสดงรูปที่บันทึกแล้วในหน้าผู้รับจ้างและช่างผู้ควบคุมงาน รูปโหลดจาก Drive ผ่าน `getWorkPhoto` ที่ตรวจ ALLOWED_EMAILS และค้นไฟล์จากประวัติของ Record ID เท่านั้น ไม่รับ Drive file ID ตามอำเภอใจ ไม่เปลี่ยนไฟล์เป็น public หากบัญชีไม่มีสิทธิ์หรือโหลดรูปไม่ได้จะมีข้อความและลิงก์เปิดใน Drive ให้ตรวจสอบสิทธิ์ Sheets/โฟลเดอร์รูป รูปในเว็บรองรับ JPEG ไม่เกินประมาณ 2 MB ตามข้อจำกัดการอัปโหลดเดิม

## รายงานเลือก WBS และแยก TR
หน้ารายงานมีตัวเลือกทุก WBS, WBS เฉพาะ และไม่ระบุ WBS จัดงานให้อยู่ติดกันตาม WBS → TR → เสา/PEA ตัดช่องว่างหัวท้ายชื่อ WBS/TR TR ที่เหมือนกันแต่คนละ WBS เป็นคนละกลุ่ม แสดงชื่อ WBS/TR ทุกหัวกลุ่ม และระบุจำนวนงาน/กลุ่มในส่วนที่พิมพ์
Excel, JSON และพิมพ์/PDF ใช้ชุดรายการที่เลือกเดียวกัน ปุ่มรายงานจากประวัติและรายงานเฉพาะรายการยังใช้งานได้ อัปเดตเฉพาะ Index.html แล้ว Deploy เวอร์ชันใหม่ ไม่ต้องแก้ Code.gs หรือชีตสำหรับฟังก์ชันนี้
ทดสอบเบราว์เซอร์ด้วย Google bridge จำลองผ่านการเลือก WBS/กลุ่ม TR/กลุ่มว่าง/ส่งออก Excel และ JSON/หัวรายงานตอนพิมพ์ การเลือกยังต้องตรวจรับบน deployment จริงหลังอัปเดต

หน้ารายงานเลือก WBS แล้วจะแสดง TR ของ WBS นั้นในช่องเลือก TR เลือก TR เดียวเพื่อพิมพ์หรือส่งออกเฉพาะ TR นั้น หรือเลือกทุก TR เพื่อรวมทั้ง WBS เมื่อเปลี่ยน WBS ระบบล้างตัวเลือก TR เดิม มีตัวเลือกไม่ระบุ TR สำหรับงานที่ยังไม่ได้กรอก TR ต้องเลือก WBS ก่อนจึงใช้ช่อง TR ได้

## ล็อกอิน DI / pass และ Admin จัดการรายชื่อ
เพิ่มหน้าเข้าสู่ระบบ DI/pass ต่อจากการตรวจบัญชี Google เดิม สมาชิกต้องอยู่ใน ALLOWED_EMAILS และมีสิทธิ์ Sheets/Drive ตามเดิม รหัสผ่านจัดเก็บด้วย bcrypt cost 10 ใน Script Properties ไม่เก็บเป็นข้อความธรรมดาและไม่คืน hash/pass ในหน้ารายชื่อ DI ใช้ตัวอักษรอังกฤษ ตัวเลข `_ . -` ไม่เกิน 64 ตัว และแยกตัวพิมพ์ใหญ่/เล็ก pass ไม่เว้นว่าง ไม่เกิน 72 ไบต์ (ข้อจำกัด bcrypt)

### อัปเดตและสร้าง Admin แรก
1. แทน Code.gs และ Index.html ด้วยไฟล์ล่าสุด
2. สร้างไฟล์ **สคริปต์** เพิ่มสองไฟล์ชื่อ `Auth` และ `Bcrypt` แล้วคัดลอก Auth.gs/Bcrypt.gs ทั้งหมดตามลำดับ ไฟล์เหล่านี้เป็น .gs ไม่ใช่ HTML คง Leaflet เดิมไว้
3. Deploy เวอร์ชันใหม่ด้วย Execute as: User accessing the web app และ Google-account-only access ตามเดิม
4. เปิดเว็บด้วยบัญชี Google เจ้าของ Sheets ที่อยู่ใน ALLOWED_EMAILS จะเห็นปุ่ม “สร้าง Admin คนแรก” กรอกชื่อ ตำแหน่ง DI และ pass ส่วนตัว แล้วสร้างบัญชี/เข้าสู่ระบบ ไม่มีรหัสผ่านเริ่มต้น ห้ามส่ง pass ในแชตหรือ commit ลง repository
5. Admin เปิดเมนู “จัดการผู้ใช้ (Admin)” เพื่อเพิ่มชื่อ ตำแหน่ง DI/pass เลือกสิทธิ์ผู้ใช้หรือ Admin และเปิด/ปิดใช้งาน การแก้รายเดิมเว้น pass ว่างเพื่อคงเดิม ตั้ง pass ใหม่จะยกเลิก session เดิม บัญชีปิดใช้งานใช้ session เดิมไม่ได้ ไม่อนุญาตปิดหรือลดสิทธิ์ Admin ที่ใช้งานได้คนสุดท้าย

ถ้าเป็น Shared Drive หรือเจ้าของ Google ที่ต้องสร้าง Admin ต่างจากเจ้าของชีต ผู้ดูแลโปรเจกต์ตั้ง Script property `LOGIN_BOOTSTRAP_EMAIL` เป็นอีเมล Google ของผู้สร้าง Admin แรกได้ ต้องเป็นบัญชีใน ALLOWED_EMAILS ใช้เฉพาะการ bootstrap ไม่ใช่รหัสผ่าน

Session อายุสูงสุด 4 ชั่วโมง อยู่ใน Script Cache และผูกกับ Google email กับ DI; cache อาจถูก Google ล้างก่อนหมดอายุ ให้เข้าสู่ระบบใหม่ จำกัดลองผิด 5 ครั้งต่อบัญชี Google ใน 15 นาที API อ่าน/บันทึก/โหลดรูปต้องมี DI session; จัดการผู้ใช้ตรวจสิทธิ์ Admin ฝั่งเซิร์ฟเวอร์ คำสั่ง Run สำหรับซิงก์ลิงก์รูปใน editor อนุญาตบัญชี Google เจ้าของชีต/LOGIN_BOOTSTRAP_EMAIL ตามเดิม

ระบบแยก Admin สำหรับจัดการรายชื่อ แต่ยังไม่จำกัดหน้า/WBS ตามตำแหน่ง ชื่อและตำแหน่งเป็นข้อมูลแสดงผล ผู้ใช้ทั่วไปยังใช้หน้าผู้รับจ้าง/ผู้ควบคุมงานได้ตามสิทธิ์เดิม **เจ้าหน้าที่ที่เป็น Editor ของโปรเจกต์ Apps Script ที่ bound กับ Sheets สามารถแก้สคริปต์/Script Properties ได้** จึงต้องเชื่อถือผู้มีสิทธิ์แก้โปรเจกต์ การแยกผู้ใช้ที่ไม่เชื่อถือจากผู้ดูแลต้องย้ายสคริปต์เป็น standalone และออกแบบสิทธิ์ Sheets/Drive ใหม่ ไม่ใช้ DI login เป็นขอบเขตป้องกัน script editors

`node patrol-google/test-auth.cjs` ตรวจ bcrypt, bootstrap เฉพาะเจ้าของ, session ผูก Google, สิทธิ์ Admin, reset/logout/last-admin/limit (Google APIs จำลอง) ชุดทดสอบงานเดิมแยก mock DI session เพื่อทดสอบ workflow แล้ว Browser mock ทดสอบฟอร์ม login/bootstrap/Admin/มือถือ ไม่ใช่ Google OAuth หรือ deployment จริง
Bcrypt.gs vendored จาก bcryptjs 2.4.3 ตรวจ SHA512 integrity ของ npm archive และมี BCRYPT-LICENSE.txt

### ประวัติการกรอกและข้อมูลประกอบงาน
WBS/TR ในหน้าบันทึกงานมีรายการแนะนำจากงานที่บันทึกสำเร็จ เก็บใน localStorage แยก DI และเบราว์เซอร์ สูงสุด 100 ค่าต่อช่อง ปุ่มลบประวัติล้างเฉพาะรายการแนะนำ ไม่ลบ DATA ประวัติงานกรอง WBS และ TR ภายใน WBS ได้
รูปสำรวจสองช่องแสดงชื่อรูปก่อนดำเนินการ 1/2 แต่ยังใช้คอลัมน์ AQ/AR เดิม รูปเก่าที่เป็นหลังดำเนินการไม่ได้ถูกเปลี่ยนเนื้อหา รูปในหน้าผู้รับจ้าง/ผู้ตรวจอ่านผ่านบัญชี Google ที่มีสิทธิ์ Drive
ผู้รับจ้างเห็นเฉพาะเมนูผู้รับจ้าง และ server ปฏิเสธ savePatrol/saveInspection สำหรับบทบาท contractor สิทธิ์นี้ไม่ป้องกันผู้มีสิทธิ์แก้ไขชีตหรือสคริปต์โดยตรง

หน้าหลักแสดง Dashboard กดการ์ดสถานะเพื่อกรองรายการ กด WBS เพื่อเปิดรายงาน กดทางลัดและอัปเดตข้อมูลได้ ผู้รับจ้างยังใช้งานเฉพาะหน้าผู้รับจ้างตามสิทธิ์เดิม รหัสผ่านไม่มีความยาวขั้นต่ำ แต่ต้องไม่ว่างและไม่เกิน 72 ไบต์ตามข้อจำกัด bcrypt

หมายเหตุการตรวจรับเก็บในคอลัมน์ K ของ InspectorReviews แยกจากหมายเหตุสำรวจ ระบบเพิ่มหัวคอลัมน์เมื่อบันทึกผลตรวจใหม่ และอ่านผลเก่าที่ไม่มีหมายเหตุได้ หน้าผู้รับจ้างแสดงผลล่าสุดและหมุดเขียว/แดงตามผ่าน/ไม่ผ่าน โหลดหน้าใหม่เพื่อรับผลที่เจ้าหน้าที่อื่นบันทึก

รายงาน/ผู้รับจ้าง/ช่างควบคุมงานแยกปุ่ม WBS และ Patrol ผู้ดูแลกำหนด workTypes ของผู้รับจ้างเป็น wbs, patrol หรือทั้งสอง (บัญชีเดิมค่าเริ่มต้นทั้งสอง) บังคับการอ่านรายการ การดูรูปและส่งมอบบน server การเปลี่ยนประเภทสิทธิ์ทำให้ต้องเข้าสู่ระบบใหม่ รายการ กฟฟ. เพิ่มผ่านเมนูจัดการผู้ใช้ เก็บใน Script Properties และคงสองรายการเดิมไว้

งาน WBS มีปีงบประมาณของงาน (ค.ศ.) แยกจากวันที่สำรวจ เก็บใน DATA คอลัมน์ BC ตัวกรองปี WBS ของ Dashboard/ประวัติ/รายงาน/ผู้รับจ้าง/ผู้ควบคุมงานใช้ปีงบประมาณ งานเก่าไม่เดาปีและเลือกกรองยังไม่ระบุปีงบประมาณได้ Patrol ยังคงกรองตามปีสำรวจ กราฟรายเดือนใช้ปีปฏิทินของวันที่สำรวจ/ส่งมอบจริงภายในชุดงานที่กรองแล้ว

รุ่นไม้แป้นเก่า: DATA แทรกคอลัมน์ AC–AE หลัง AB เป็นเก่า-ไม้แป้น 20/60/120 อัตโนมัติเมื่อโหลดข้อมูล ตรวจหัวตารางเดิมก่อนแทรก และไม่แทรกซ้ำ คอลัมน์ด้านขวารวมรูป/Patrol/ที่อยู่/CA/ปีงบประมาณเลื่อน 3 ช่องตามข้อมูลเดิม กรุณาอัปเดต Code.gs และ Index.html พร้อมกัน ไม่ต้องแทรกคอลัมน์เอง

ช่างผู้ควบคุมงาน/Admin ส่งต่องาน U_CUBE ผมต. เป็น U_CUBE ผู้รับจ้างได้ โดยใช้ Record ID เดิม ระบุเหตุผลและบันทึก audit ใน PatrolTransfers ผลตรวจเดิมยังอยู่ InspectorReviews แต่ไม่นับเป็นผลตรวจของขั้นตอนผู้รับจ้าง ต้องตรวจรับใหม่หลังส่งมอบ ไม่ลบรูปสำรวจเดิม

### แผนที่ภาพประกอบรายงาน WBS
ในรายงานเลือก WBS/TR และปี แล้วแนบภาพ JPEG/PNG ลากกรอบสี่เหลี่ยมเฉพาะบริเวณงาน ก่อนกดบันทึก ระบบเก็บเฉพาะภาพที่ตัดแล้วใน PHOTO_FOLDER_ID และประวัติใน ReportMaps แยกตาม WBS/TR/ตัวกรองปี ไม่เปลี่ยนพิกัดหรือหมุดสำรวจ ผู้ดูแลและผู้ควบคุมงานบันทึกภาพได้ ผู้รับจ้างอ่านได้เฉพาะรายงานที่มีสิทธิ์ ภาพที่บันทึกแล้วจะแสดงในพิมพ์/PDF การเลือก “ทุก TR” หรือ “ทุกปี” เป็นภาพคนละชุดกับ TR/ปีเฉพาะ ต้องอัปเดต Code.gs และ Index.html พร้อมกัน

การกำหนดเสาในภาพแผนที่: เลือกพื้นที่งานก่อน แล้วเลือกโหมดกำหนดเสา คลิกตรงสัญลักษณ์สี่เหลี่ยมแต่ละเสา ระบบเรียง A–Z แล้วต่อ AA, AB, AC… แบบ Excel ภายในกลุ่มเดิม (สูงสุดรวม 500 เสาต่อภาพ) เพิ่มชื่อกลุ่มใหม่เพื่อเริ่ม A อีกครั้งได้ ภาพที่บันทึกมีตัวอักษรและคำอธิบายสีแนบอยู่ด้วย metadata กลุ่มเก็บใน ReportMaps ไม่แก้พิกัดหรือช่องเสาที่ของ DATA หากต้องทำภาพใหม่ให้แนบภาพต้นฉบับใหม่

### ชุดแผนที่หลายภาพและเสาต่อเนื่อง
ใช้ WBS/TR/ตัวกรองปีเดียวกันแล้วเพิ่มภาพใหม่เข้าชุด เก็บแต่ละภาพเป็นรายการใน ReportMaps และเรียงตามเวลาบันทึก ภาพเดิมรุ่นก่อนรองรับชุดจะแสดงเฉพาะรุ่นล่าสุดเป็นภาพแรก ไม่เอาภาพเก่าที่เคยแทนที่มารวมเป็นภาพซ้ำ กลุ่มชื่อเดียวกันนับรหัสเสาต่อจากรหัสสูงสุดในภาพก่อน (Z → AA) ส่วนเสาซ้อนกันเลือก “เสาเดิม” เพื่อใช้รหัสเดิม ไม่เพิ่มจำนวนเสารวม ระบบตรวจ snapshot revision ขณะบันทึกภายใต้ lock เพื่อกันผู้ใช้สองคนกำหนดรหัสใหม่ซ้ำกัน ต้องโหลดชุดใหม่ก่อนทำต่อเมื่อมีผู้เพิ่มภาพแทรก แสดงภาพทีละหน้า หรือกดแสดงทุกภาพก่อนพิมพ์/PDF

เมนูแผนที่สำรวจ: ย้ายตัวเลือก WBS/TR/ปี ชุดแผนที่ ตัดรูป และกลุ่มเสาออกจากรายงานมาไว้เมนูแผนที่สำรวจใต้รายงาน ใช้ ReportMaps เดิมและ key เดิม จึงไม่ต้องแนบภาพซ้ำ หน้าใหม่นี้มีพิมพ์/PDF ของชุดแผนที่แยกต่างหาก

หน้าแผนที่สำรวจกรอกปีงบประมาณ พ.ศ., WBS และ TR เองได้ พร้อมรายการแนะนำจาก DATA และชุดแผนที่ที่บันทึกไว้ กด “เปิด / สร้างชุดแผนที่” หลังกรอก ผู้ดูแล/ผู้ควบคุมงานสร้างชุดก่อนมีข้อมูลสำรวจได้ ผู้รับจ้างยังอ่านได้เฉพาะชุดที่สัมพันธ์กับข้อมูลงานซึ่งมีสิทธิ์ การพิมพ์เปลี่ยนตัวกรองจะไม่เปลี่ยนชุดที่กำลังแก้ไขจนกดเปิด และระบบป้องกันการบันทึกภาพจากชุดเก่าไปยังข้อมูลที่พิมพ์ใหม่โดยไม่เปิดชุดก่อน

## การโหลดรูปบนเน็ตช้า
รูปที่บันทึกแล้วโหลดเมื่อเลื่อนมาถึงโดยไม่ขึ้นหน้าต่างรอเต็มจอ ส่วนรูปในรายงาน Patrol โหลดทันทีหลังกดปุ่มเพื่อให้พิมพ์ครบ รูปสำรวจ ส่งมอบ และตรวจรับใช้เกณฑ์ด้านยาวสุด 1100 px เหมือนกัน รูปที่โหลดแล้วเก็บใน IndexedDB ของเครื่อง แยกตาม DI และลิงก์รูป เก็บล่าสุดไม่เกิน 300 ชุด และล้างเมื่อกดออกจากระบบ ถ้าเครื่องใช้ IndexedDB ไม่ได้ ระบบโหลดรูปจาก Google ตามปกติ อัปเดตเฉพาะ Index.html แล้ว Deploy เวอร์ชันใหม่ ไม่ต้องแก้ Code.gs หรือชีต
`node patrol-google/test-photo-loading.cjs` และ `node patrol-google/check-photo-loading.cjs` ใช้ Google bridge จำลอง ไม่ยืนยัน IndexedDB ภายใต้ iframe ของ Apps Script จริง ต้องตรวจบน Test deployment และโทรศัพท์จริง

รูปย่อ: หน้าผู้รับจ้าง ผู้ควบคุมงาน และการแก้ไขงาน แสดงรูปย่อจาก Drive ผ่าน `getWorkPhotoThumbnails` ซึ่งตรวจสิทธิ์แบบเดียวกับรูปเต็มและรวมรูปทุกประเภทของงานเดียวกันเป็นคำขอเดียว ถ้า Drive ยังไม่มีรูปย่อจะส่งรูปเต็มแทน กด “ดูรูปเต็ม” เพื่อโหลดรูปเต็ม `sheet_()` อ่านหัวตารางครั้งเดียวเมื่อโครงสร้างครบ และยังปฏิเสธหัวตารางที่ไม่ตรงเหมือนเดิม ต้องอัปเดต Code.gs และ Index.html พร้อมกัน `node patrol-google/test-photo-server.cjs` ใช้ Google APIs จำลอง ขนาดรูปย่อจริงต้องตรวจบน deployment

การเปิดเว็บและแผนที่: `doGet` ส่ง build id ของเอกสารแอป ถ้าเครื่องมีเอกสารของ build เดียวกันจะเปิดจาก IndexedDB โดยไม่เรียก `getAppDocument` และ Deploy ใหม่จะโหลดเอกสารใหม่เอง หลัง session กลับมาใช้ได้ `getLoginInfo` กับ `getAccountSession` ทำงานพร้อมกัน และ `listElectricityOffices` ไม่ขวางรายการงาน รูปแผนที่โหลดโดยไม่บังจอและเก็บในเครื่องไม่เกิน 40 ภาพ ผู้ดูแลและผู้ควบคุมงานไม่อ่าน `DATA` ตอนตรวจขอบเขตแผนที่ เสาที่สำรวจแล้วแสดงเฉพาะสีเขียว ไม่มีเครื่องหมายถูกบนเสา `node patrol-google/test-map-startup-server.cjs` และ `node patrol-google/check-app-startup.cjs` ใช้ Google APIs จำลอง

แผนที่ในการ์ดบันทึกงาน WBS: แตะเสาที่ยังไม่มีงานเพื่อเปิดฟอร์มเป็น pop-up เหนือแผนที่ ปี WBS TR และเสามาจากแผนที่ บันทึกแล้วกลับแผนที่และเสาเป็นสีเขียว เสาที่มีงานแล้วแสดงรายการงานก่อน และเพิ่มงานได้จากปุ่ม “บันทึกงานที่เสานี้” ถ้าฟอร์มมีข้อมูลค้างจะถามก่อนย้ายไปเสาอื่น ตรวจด้วย `node patrol-google/check-survey-popup.cjs`

หน้าบันทึกงาน WBS แสดงเฉพาะปีงบประมาณ WBS และ TR เมื่อกรอกครบแล้วแผนที่จะเปิดเอง และเปิดซ้ำเองเมื่อค่าเปลี่ยนเท่านั้น ฟอร์มส่วนที่เหลืออยู่ใน pop-up งาน WBS ใหม่ต้องบันทึกผ่านแผนที่ จึงต้องสร้างชุดแผนที่ก่อน ส่วนการแก้ไขงานเดิมและบันทึกงาน Patrol ยังแสดงฟอร์มเต็ม

จำนวนพัสดุ: ช่องตัวเลขมีแถบเลื่อน (สายไฟ 0–100 อื่น ๆ 0–20) และยังพิมพ์ค่าที่มากกว่านั้นเองได้ งาน WBS หุบหมวดพัสดุปรับปรุง (ใหม่) ไว้ใต้หัวข้อที่กดกางได้และแสดงจำนวนรายการที่มีค่า ระบบยังเติมสูตรให้เองเมื่อเลือกขนาด/เฟส ขนาดเสา และเครื่อง งาน Patrol เริ่มแบบกางไว้ และซ่อนเฉพาะปุ่มเติมสูตรกับข้อความสถานะ ตรวจด้วย `node patrol-google/check-material-slider.cjs`

## สแกนบาร์โค้ด PEA ในฟอร์ม WBS / Patrol (รวม APK Android)

APK รุ่นปัจจุบันเปิดเว็บด้วย Chrome Custom Tabs ปุ่ม **▥ สแกนบาร์โค้ด** อยู่ข้างช่อง PEA ในทั้งสองฟอร์ม สำหรับ WBS ให้เปิดฟอร์มของเสาบนแผนที่ก่อนตามขั้นตอนเดิม กดปุ่มแล้วอนุญาตกล้องให้ Chrome/เว็บไซต์ เล็งบาร์โค้ดเส้นให้เห็นครบโดยไม่ต้องถ่ายรูป ระบบอ่านค่าตรงกันสองครั้งก่อนหยุดกล้อง แสดงหมายเลขให้ตรวจแล้วกด **ใช้หมายเลข PEA** จึงแทนค่าในช่อง โดยคงศูนย์นำหน้าและข้อมูลช่องอื่น ไม่บันทึกงานอัตโนมัติ

การอัปเดตใน Apps Script ต้องแทนไฟล์ **Index.html**, **Code.gs** และสร้างไฟล์ HTML ชื่อ **Barcode** แล้ววางโค้ดจาก `Barcode.html` ทั้งไฟล์ (เป็น JavaScript โดยตรง ไม่ต้องเติมแท็ก script) จากนั้น Deploy เวอร์ชันใหม่โดยใช้ URL เดิม เปิด APK ใหม่เพื่อโหลดหน้าใหม่ **ไม่ต้องติดตั้ง APK ใหม่**

ตัวอ่าน `@zxing/library` 0.21.3 ถูกเก็บใน `Barcode.html` และโหลดผ่าน `getPeaBarcodeDecoder` หลังตรวจสิทธิ์ ไม่ต้องโหลด CDN ระหว่างสแกน ใบอนุญาต Apache-2.0 อยู่ใน ZXING-LICENSE.txt ต้นฉบับ: https://cdn.jsdelivr.net/npm/@zxing/library@0.21.3/umd/index.min.js ; SHA-256 ของไฟล์ที่รวมข้อความระบุแหล่งที่มา: `a71c8506bc0ce7df656c62bf1e04f31f5b923c6991e68f37d593502bbb6aca35`

รองรับ Code 128/39/93, ITF, EAN, UPC และ Codabar ที่เป็นตัวเลข ไม่ใช่การอ่านตัวเลขบนจอหน่วยหรือ QR เมื่ออ่านได้ ให้เทียบหมายเลขกับ PEA บนมิเตอร์ก่อนยืนยัน ปิดกล้องเมื่อได้ผล ยกเลิก ออกจากหน้า เปลี่ยนฟอร์ม หรือเว็บอยู่เบื้องหลัง หากกล้องถูกปฏิเสธ/ไม่มี/ถูกแอปอื่นใช้จะแจ้งเหตุผล และยังกรอก PEA เองได้ตามเดิม

ตรวจด้วย `node patrol-google/check-pea-barcode.cjs`: อ่าน CODE128 จริงจากวิดีโอจำลองใน Chromium ผ่านตัวถอดรหัสที่แจกพร้อมเว็บ ตรวจ leading zero, การยืนยันก่อนแก้ช่อง, ข้อมูลฟอร์มไม่เปลี่ยน, ไม่มีการบันทึกอัตโนมัติ และการปิดกล้อง/ยกเลิกระหว่างขอสิทธิ์ ทั้ง WBS popup และ Patrol ที่หน้าจอมือถือ/คอมพิวเตอร์ ยังไม่ได้ทดสอบกล้องจริงบนมือถือหรือสิทธิ์กล้องจาก Google Apps Script deployment จริง

## APK 1.3.0: สแกนแล้วส่ง/กลับ/เติม PEA เอง

ติดตั้ง APK 1.3.0 แล้วแทนทั้ง **Index.html และ Code.gs** จากนั้น Deploy ด้วย URL เดิม ดู [ขั้นตอน APK](../android/README.md#สแกน-native-และเติม-pea-อัตโนมัติใน-apk-130) ใช้กล้องใน APK และส่งผลเข้าช่อง PEA ของฟอร์มที่เริ่มสแกนเอง ไม่ใช้คลิปบอร์ด ไม่ต้องกดวาง และไม่บันทึกงานอัตโนมัติ

เว็บสร้างคำขอชั่วคราวผ่าน `prepareNativePeaScan` หลังตรวจ session/Google user เก็บเจ้าของคำขอและวันหมดอายุใน CacheService 5 นาที APK ส่ง request ID กับเลขผ่าน browser callback ของ deployment เดิม `doGet` ตรวจ Google เจ้าของคำขอและยอมรับค่าเดิมซ้ำได้ แต่ไม่ให้เปลี่ยนค่าเดิม เว็บเดิมรับผลผ่าน `getNativePeaScan` ซึ่งตรวจบัญชีและ session แล้วจึงเติมช่อง หากยกเลิก/เปลี่ยนฟอร์มจะละทิ้งผลล่าช้า ไม่เปลี่ยนสิทธิ์เผยแพร่ ไม่ต้องทำ public API หรือเก็บรหัสผ่านใน APK

รุ่น 1.3 ส่งผลทันทีเมื่ออ่านเลขตรงกันสองครั้ง ไม่แสดงหน้ากดใช้เลข APK ผูก Custom Tabs session กับ native navigation callback เพื่อคืนแท็บเดิมเองเมื่อรับผลเสร็จ หน้ารับผลแสดงเพียงกำลังดำเนินการ ไม่แสดงหน้ารับรอง PEA ปุ่มกลับสำรองจะแสดงหลัง 8 วินาทีเมื่อ callback/การเปิดแอปถูกบล็อก ต้องเชื่อมต่ออินเทอร์เน็ตและใช้บัญชี Google เดียวกับฟอร์ม คำขอหมดอายุหรือถูก evict จาก CacheService ให้กดสแกนใหม่

ทดสอบ `node patrol-google/test-native-pea-auto.cjs` และ `node patrol-google/check-native-pea-handoff.cjs` ผ่าน backend/browser ที่จำลองการสแกนและ browser callback ยังไม่ได้ทดสอบการสลับแอป/กล้องจริงบนมือถือ

## ส่งมอบไม่ได้: Access denied: DriveApp

เว็บทำงานแบบ User accessing the web app รูปส่งมอบสร้างใน PHOTO_FOLDER_ID ด้วยบัญชี Google ที่กำลังใช้เว็บอยู่ การเป็นผู้รับจ้างในรายชื่อ DI ไม่ได้ให้สิทธิ์ Google Drive โดยอัตโนมัติ

ให้เจ้าของโฟลเดอร์/ผู้ดูแลเปิดโฟลเดอร์จาก PHOTO_FOLDER_ID ใน Script properties แล้วแชร์ให้ **บัญชี Google ที่ผู้รับจ้างใช้จริงเป็น Editor** (ผู้แก้ไข) รวมถึงตรวจว่าบัญชีนั้นอนุญาต scope Google Drive ให้แอปครบแล้ว หากเป็น Workspace ให้ตรวจนโยบาย Drive/การอัปโหลด/แอป OAuth ขององค์กรด้วย ไม่ต้องเปลี่ยน Execute as และไม่ต้องแชร์รูปแบบสาธารณะ

โค้ดรุ่นนี้แยกข้อความปฏิเสธสิทธิ์ Drive จากปัญหาเครือข่าย/โควตา แจ้งบัญชี Google และว่าล้มเหลวตอนเปิดโฟลเดอร์หรือเพิ่มรูปที่ 1/2 แล้วแสดงปุ่มเปิดโฟลเดอร์/ขอสิทธิ์ และปุ่มอนุญาต Google ให้แอปเมื่อ ScriptApp รายงานว่าต้องอนุญาตเพิ่ม เปิดในแท็บใหม่เพื่อเก็บรูปที่เลือกในฟอร์มเดิม แก้สิทธิ์แล้วกลับมากดส่งมอบซ้ำด้วยรูปเดิมและ request ID เดิมได้ ไม่มีการอ้างว่าส่งมอบสำเร็จก่อนเขียน ledger สำเร็จ

ต้องแทนทั้ง Code.gs และ Index.html แล้ว Deploy ด้วย URL เดิม การอัปเดตโค้ดช่วยวินิจฉัยและเปิดขั้นตอนแก้ไข **ไม่ได้ให้สิทธิ์ Drive แทนเจ้าของโฟลเดอร์** ตรวจในโฟลเดอร์จริงโดยใช้บัญชีผู้รับจ้างว่ามีสิทธิ์เพิ่มไฟล์ หลังแก้สิทธิ์จึงทดสอบส่งมอบอีกครั้ง

ตรวจด้วย test-contractor.cjs และ check-delivery-drive-access.cjs: จำลองการถูกปฏิเสธตอนอ่านโฟลเดอร์/เขียนรูปที่สอง คืนไฟล์ที่ยังไม่บันทึก ไม่เพิ่ม ledger ปลอม คงรูปในฟอร์ม และส่งซ้ำสำเร็จหลังคืนสิทธิ์โดยไม่สร้างรายการซ้ำ ยังไม่ได้แก้สิทธิ์หรือตรวจ ACL บน Google Drive จริงจาก workspace นี้

## แผนที่งานผู้รับจ้าง/ช่างผู้ควบคุมงาน: ซูมและเต็มจอ

สองหน้าซูมได้ไกลกว่าระดับสูงสุดเดิม 50% ในเชิงระยะภาพ (`19 + log2(1.5)`) ใช้ภาพแผนที่ระดับ 19 ขยายต่อ ไม่เรียก tile ระดับ 20 ที่ไม่มี รองรับซูมครึ่งระดับและสูงสุดเป็นเศษระดับเพื่อให้ครบ 150% หมุด/พิกัดและข้อมูลกลุ่มเสาไม่เปลี่ยน

ปุ่ม **⛶ เต็มจอ** เปิดแผนที่เต็มพื้นที่หน้าเว็บทั้งแนวตั้ง/แนวนอน ใช้ HTML dialog เพื่อรองรับมือถือรวม iOS โดยไม่พึ่ง Fullscreen API ของเบราว์เซอร์ กด **✕ ปิดเต็มจอ** หรือ Escape เพื่อคืนตำแหน่งแผนที่เดิม คงจุดกึ่งกลาง ระดับซูม และรูปที่ยังไม่ได้ส่งไว้ เมื่อเลือกหมุดเดี่ยว/กลุ่มหรือเปิดงาน จะออกจากเต็มจอแล้วเลื่อนไปหัวข้อรายละเอียดงานให้อัตโนมัติ โดยเว้นพื้นที่แถบหัวเว็บ การเปลี่ยนหน้าหรือกลับหน้าเข้าสู่ระบบจะคืนแผนที่และปลดการล็อกเลื่อนเสมอ

อัปเดตเฉพาะ Index.html แล้ว Deploy ด้วย URL เดิม APK เดิมใช้ได้ การเต็มจอหมายถึงพื้นที่เว็บแอป ไม่ได้ซ่อนแถบระบบ/แถบ Google ที่อยู่นอก iframe

ตรวจด้วย `node patrol-google/check-work-map-fullscreen.cjs`: ซูมสูงสุด 1.5 เท่าโดย native tile อยู่ระดับ 19 เปิด/ปิด/Escape เต็ม viewport เลือกหมุด WBS/Patrol แล้วไปงาน กลุ่มเสา ข้อมูลเดิม/รูปยังไม่ส่ง และ cleanup เมื่อเปลี่ยนหน้า ที่หน้าจอ 390×844, 844×390 และ 1280×900 ผ่าน Chromium จำลอง ยังไม่ได้ตรวจ Safari บน iPhone จริง

## มินิแผนที่ WBS และภาพกำหนดเสาเต็มจอ

อัปเดตทั้ง `Index.html` และ `Code.gs` แล้วอัปเดต deployment เดิม ไม่ต้องแก้ manifest หรือย้ายข้อมูลเดิม

- ตอนแนบภาพเพื่อกำหนดเสา กด **ขยายรูปเต็มจอเพื่อกำหนดเสา** เลือกแนวหลัก/แนวแยกในแถบตั้งค่าได้ มือถือแตะเพื่อวางเสา ลากเพื่อเลื่อน และจีบนิ้วเพื่อซูม การลากหรือซูมไม่เพิ่มจุดเสา กดพอดีรูปหรือกลับหน้าปกติได้โดยจุดที่วางไว้ยังอยู่
- ที่หน้า **แผนที่สำรวจ** เลือกปี/WBS/TR ให้ครบ แล้วเปิด **มินิแผนที่ / จัดแนวสาย** ระบบนำเข้าเสาที่กำหนดบนภาพเป็นตำแหน่งเริ่มต้น ไม่มีการเดาเส้นเชื่อมจากภาพ และไม่ใช้บริการ AI เจนภาพ ลากจุดเพื่อจัดแผนผังให้อ่านง่ายได้
- เลือกเสาแรกแล้วสร้างแนวหลัก จากนั้นแตะเสาถัดไปตามลำดับ กดจบแนวเพื่อหยุดเชื่อม เลือกเสาปากซอยเพื่อเพิ่มแนวซอย และแยกซอยย่อยจากจุดในแนวซอยได้ เมื่อกลับไปสำรวจแนวเดิม ให้เลือกแนวเดิมและกดต่อแนว ระบบต่อจากจุดสุดท้ายของแนวนั้น ไม่เชื่อมข้ามจากปลายซอยย่อย
- กำหนดจุดเริ่มสำรวจและตำแหน่ง TR แยกกันได้ เฟสแต่ละแนวเริ่มเป็นรอตรวจสอบหน้างานเสมอ คนสำรวจจึงเลือก A–N, B–N, C–N หรือ A–B–C–N แล้วกด **บันทึกมินิแผนที่ / เฟส** ข้อมูลนี้แยกจากขนาด/เฟสของมิเตอร์
- เปิดจากหน้า **บันทึกงาน WBS** ได้ด้วย แตะเสาแล้วกดบันทึกงาน WBS ที่เสานี้เพื่อเปิดฟอร์ม สีของเสาอ้างอิงงานที่โหลดแล้วจากชุดปี/WBS/TR เดียวกัน การจัดตำแหน่งมินิแผนที่ไม่แก้ LatLong ของงานหรือพิกัดนำทาง
- ข้อมูลแผนผังและประวัติผู้ยืนยันเฟสจัดเก็บในชีต `MiniSurveyMaps` ซึ่งสร้างเมื่อบันทึกครั้งแรก แยกตามปี/WBS/TR ผู้ดูแลและช่างผู้ควบคุมงานแก้ไขได้ ผู้รับจ้างดูได้ตามสิทธิ์งานเดิม รองรับ 500 จุด / 100 แนว และ JSON ไม่เกิน 45,000 ตัวอักษรต่อชุด มีตรวจรุ่นข้อมูลป้องกันเขียนทับจากอีกเครื่อง
- มินิแผนที่เป็นแผนผัง ไม่ตามมาตราส่วน และพิกัดวาดไม่ใช่ GPS ไม่จำเป็นต้องเก็บ GPS ครบทุกเสาก่อนใช้งาน

ตรวจด้วย `node patrol-google/test-mini-survey-map.cjs` และ `node patrol-google/check-mini-survey-map.cjs` จากราก repository การทดสอบเบราว์เซอร์ใช้ข้อมูลจำลอง ควรลองกับงานจริงหนึ่งชุดหลัง deploy ก่อนใช้สำรวจทั้งแนว
